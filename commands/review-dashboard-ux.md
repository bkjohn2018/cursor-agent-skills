Review a dashboard or analytics webspace for decision support, navigation clarity, visual hierarchy, and usability.

Collect these inputs first:
- Screens or pages to review
- Primary users and their core decisions
- Known pain points or suspected UX issues
- Desired review depth: quick, standard, comprehensive
- Screenshot(s), prototype links, or implementation references

Review by gate:

1. **Product fit**
   - Apply `dashboard-product-framing`.
   - Check whether the page supports real user decisions and core jobs to be done.

2. **Information architecture**
   - Apply `dashboard-information-architecture`.
   - Check navigation clarity, drill paths, section hierarchy, and path from signal to action.

3. **Dashboard design**
   - Apply `finance-dashboard-design` when the dashboard is finance-led, KPI-dense, or a governed operating surface.
   - Check quick-scan usability, diagnostic depth, and interaction predictability.

4. **Narrative and visual clarity**
   - Apply `analytics-storytelling`.
   - Check clutter, focus, takeaway-oriented headers, and whether visuals emphasize the right message.

Output must include:
1. UX review summary
2. Findings by severity: critical, major, minor
3. IA/navigation issues
4. Visual hierarchy and clarity issues
5. Recommended fixes in priority order
