# Phase 6: Use – Do & Check

**Goal**: Release and monitor. Track how finance/accounting team uses documentation; log exceptions, user questions, process deviations.

**ISO 9001 alignment**: Clause 8.1 (operational control) and 9.1.3 (analysis and evaluation). Monitor whether the procedure is being used as intended and delivering the intended results.

---

## Steps

### 1. Release and Communicate

**Announce to finance team**:
- Email or team message: "Procedure [Title] is now effective as of [date]"
- Include location (link or path)
- Highlight key changes from prior version (if revision)
- Identify owner contact for questions
- Note any training or transition date (if major change)

**Example**:
```
PROCEDURE EFFECTIVE: GL Reconciliation SOP v2.0

Location: [Sharepoint link]
Owner: Jane Smith (jane.smith@company.com)
Effective Date: June 1, 2025
Version: 2.0 (supersedes v1.1 from May 2024)

KEY CHANGES:
- Updated variance tolerance thresholds: now $2,500 (was $1,500)
- New escalation path for variances >$10,000 requires CFO approval
- Added process for unreconciled items lasting >60 days

QUESTIONS? Contact Jane Smith.
```

---

### 2. Monitor Usage and Feedback

**Capture user feedback**:
- **Training/onboarding**: Track how new hires use the procedure; where do they get stuck?
- **Helpdesk tickets**: Are users asking questions about this procedure? What questions?
- **Process variance**: Are users deviating from the documented procedure? Why?
- **Compliance checks**: Do control reviews show the procedure is being followed?
- **User surveys**: (Optional) Ask users: "Is this procedure clear? Missing anything?"
- **Customer metrics**: User satisfaction surveys (e.g., "Is this procedure clear and usable?"), usage frequency, error rates tied to documentation

**How to collect**:
- **Informal**: Owner stays in touch with users; notes questions, gaps, deviations
- **Formal**: Monthly or quarterly review of helpdesk tickets, audit findings, user feedback
- **Structured**: Feedback form (optional) or brief survey attached to document
- **Targeted**: Ask representative finance/accounting users after release whether the document is accurate, current, accessible, and usable

**Log feedback**:
```
DOCUMENTATION USAGE LOG – GL Reconciliation SOP
─────────────────────────────────────────
Date       | Feedback/Issue        | User/Role | Customer Impact       | Action Taken
2025-06-05 | Unclear variance...   | AR Staff  | Delay; user asked mgr  | Noted for v2.1
2025-06-12 | Which GL code for...  | AR Lead   | Risk of miscoding      | Clarify in next review
2025-07-01 | System screenshot... | Finance   | Confusion after patch  | Update screenshot for v2.1
─────────────────────────────────────────
```

**Minimum customer feedback evidence**:
- Feedback source and date.
- User role or customer group.
- Customer impact.
- Owner response.
- Decision: no action, clarify, revise, train, escalate, or open corrective action.

### 3. Track Deviations and Nonconformities

**Process deviations** (users not following documented procedure):
- When variance tolerance is exceeded but not escalated
- When a user skips a step because they think it's redundant
- When system change makes documented steps impossible
- When user finds a workaround because documentation is unclear

**Log deviations**:
- What deviation occurred?
- Why? (user confusion, procedure gap, system issue, risk mitigation)
- Who did it? (role, not name; for pattern analysis)
- Impact? (did it cause an error, delay, or control weakness?)
- Was the deviation caused by a documentation issue or by user behavior/training?

**Nonconformities** (documented findings from audit or control review):
- Audit notes: "Variance not escalated per SOP"
- Control review: "Two users following different steps for same task"
- Compliance finding: "Procedure doesn't reference required approval"
- User feedback: "Approved procedure is unclear or missing required steps"
- Document control issue: "Users relied on an outdated emailed copy"

**Classify documentation nonconformities**:
- **Accuracy**: Process, system, threshold, role, account, or calculation is wrong.
- **Currency**: Document is stale, superseded, or not reviewed by cadence.
- **Availability**: Users cannot find or retrieve the controlled copy.
- **Usability**: Users cannot follow the procedure without avoidable confusion.
- **Protection**: Unauthorized edits, uncontrolled copies, or multiple current versions exist.
- **Traceability/retention**: Review, approval, revision, retirement, or exception evidence is missing.

**Log nonconformities**:
```
NONCONFORMITY LOG
─────────────────────────────────────────
Date Found | Nonconformity          | Category   | Root Cause           | Action / Evidence
2025-06-15 | Variance not escalated  | Usability  | User missed Step 8   | Retrain user; clarify Step 8 in v2.1
2025-07-01 | Missing CFO approval    | Accuracy   | Procedure unclear    | Add CFO signature block in v2.1
2025-07-10 | Old PDF used            | Protection | Uncontrolled copy    | Remove copy; send controlled link
─────────────────────────────────────────
```

Escalate to corrective action when nonconformities recur, affect high-risk controls, create audit exposure, or show a weakness in ownership, review cadence, storage control, access, or customer feedback handling.

---

### 4. Assess Control Effectiveness

**Monthly or quarterly**:
- Did the control operate as documented?
- Were variances identified and escalated on time?
- Did approvals happen at right level?
- Were there gaps or process deviations?

**Document control assessment**:
```
CONTROL EFFECTIVENESS REVIEW – GL Reconciliation
─────────────────────────────────────────
Period:           June 2025
Control Owner:    Jane Smith
Procedure:        GL Reconciliation SOP v2.0

OPERATING EFFECTIVELY?
☐ Yes – No exceptions; control performed as documented
☐ Mostly Yes – 1–2 minor deviations; no impact
☒ Partially – Multiple deviations or design gaps; needs revision
☐ No – Control not working; major rework needed

FINDINGS:
- Variance escalation working well (5 variances escalated correctly in June)
- User confusion on Step 5: 3 users asked for clarification
- System issue: Screenshots in Steps 6–7 outdated after system patch

ACTION ITEMS:
- Revise Step 5 language for v2.1 (July 2025)
- Update system screenshots in Steps 6–7 (July 2025)
- Owner to retrain one user who deviates at Step 4
─────────────────────────────────────────
```

---

### 5. Maintain Usage Documentation

**Keep evidence** that control is operating:
- Reconciliation sign-offs (evidence procedure was followed)
- Variance logs (evidence deviations were tracked)
- Training records (evidence users were trained)
- Email threads (evidence questions were answered, gaps identified)

**For audit trail**:
- Store together with procedure version
- Retain per policy (typically 3–7 years)
- Enables auditor to see: procedure exists, was followed, deviations were tracked

---

## Use Monitoring Checklist

During the use phase, track:

- [ ] User feedback collected (questions, confusion, gaps)
- [ ] Customer perception reviewed for accuracy, currency, accessibility, and usability
- [ ] Deviations from documented procedure logged
- [ ] Nonconformities reported and documented
- [ ] Recurring issues assessed for corrective action
- [ ] Control effectiveness assessed (quarterly or per schedule)
- [ ] Training or clarification provided to users
- [ ] Issues logged for next review cycle (Phase 7)
- [ ] Evidence of control operation retained (sign-offs, logs, approvals)
- [ ] Feedback, deviation, nonconformity, exception, and response evidence retained

---

## Common Pitfalls

| Pitfall | Why It Matters | How to Avoid |
|---|---|---|
| No feedback mechanism | Users frustrated; gaps unknown; procedure never improves | Owner proactively asks users; sets up simple feedback channel |
| Deviations not logged | Pattern of misuse invisible; risk flies under radar | Owner or manager tracks deviations; reviews monthly |
| No control assessment | Procedure may not be working; nonconformities missed | Quarterly review of variance logs, audit findings, user questions |
| Issues noted but ignored | Documentation remains broken; users continue to struggle | Log issues; prioritize for revision (Phase 7); set timeline |
| Feedback lost | Owner remembers issues but doesn't track; important gaps forgotten | Use simple log or spreadsheet; maintain as living document |

---

## Output: Use and Monitoring Records

By the end of this phase (ongoing), you should maintain:

1. **User feedback log** (questions, confusion, gaps)
2. **Deviation log** (when/why users deviated from procedure)
3. **Nonconformity log** (audit findings, control gaps)
4. **Control effectiveness assessment** (quarterly or per schedule)
5. **Corrective action candidates** for recurring or high-risk documentation issues
6. **Evidence of control operation** (sign-offs, logs, approvals, training records)

These outputs feed into **Phase 7 (Revise)** to improve documentation.
